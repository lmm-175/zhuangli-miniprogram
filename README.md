# 妆历

**同城化妆师的排班本 + 接单本。** 微信小程序 · 原生开发 · 零依赖 · 个人独立完成。

> 一个妆娘一天要接十几单。她现在的工具是一张纸加满屏微信聊天记录 ——
> 「5 月 2 日 10:00 / 10:30 / 11:00…」手写一遍，顾客挨个问「我约几点」，她再挨个翻回去找。
> 妆历把这两件事接过来：**填六个数字，排出一整天的妆位表**；顾客点开链接，**自己挑还空着的那个**。

**▶ [点这里看完整的界面走查稿](https://lmm-175.github.io/zhuangli-miniprogram/)** —— 18 个页面、73 个可点元素，每一处都点得动。

---

## 两个角色

| | 妆师（接单的人） | 约妆端（顾客） |
|---|---|---|
| **底栏** | 档期 · 预约单 · 我的 | 我约过的妆娘 · 我的预约 · 我的 |
| **核心事** | 排版、管单、推进状态 | 挑妆位、填单、看自己的预约 |
| **登录** | — | ⛔ **不需要注册、不需要登录** |

一条分享链接就能把一个陌生人变成一张预约单 —— 这是整个产品里我最在意的一条路。

## 工程数据

| | |
|---|---|
| 页面 | **18 个**（`app.json` 注册） |
| 代码 | **82 个文件、约 9,500 行**（JS / WXML / WXSS / JSON） |
| 依赖 | **0** —— 没有 `package.json`、没有 `node_modules`、没有 UI 库、不用 TS |
| 自测 | **1,395 条断言**，纯 Node 跑，无测试框架 |
| 数据 | 全部在**本机 storage**（7 个 key），唯一会写云端的是「问题反馈」 |
| 导航 | 自定义导航栏 + **自绘 tabBar**（微信全局只有一个 tabBar，而两个角色要的格子不一样） |

自测不是摆设 —— 它救过好几次。有两类 bug **肉眼看不出、开发者工具也不报**：

- `wx.hideKeyboard()` 会打断触摸序列，紧跟的 `wx.showModal` 被整个吃掉 —— 表现是「点了一下什么都没有」；
- 把软删除的记录当底稿写回 storage，**把用户唯一的凭据真删了**，而操作路径隔着一整页。

这两条都写成了断言，钉在 `妆历 自测.js` 里。

## 最花心思的地方：合规倒推产品形态

这个项目最特别的一点是 —— **产品形态不是先想出来的，是被审核规则倒推出来的。**

个人主体小程序有一份**类目白名单**，没有社交、电商、文娱、资讯。第一次提审被驳回，原话是：

> 涉及用户自行生成内容（图片）的记录、分享，属**社交-笔记**范畴，为**个人主体小程序未开放类目**。

于是整条产品线掉头，砍掉了三块本来做好的东西，并且**每砍一块都写清了为什么**：

| 砍掉的 | 为什么 |
|---|---|
| **公域发现**（妆娘目录 / 推荐 / 按风格找人） | 一份能被一页页翻完的公开列表 = 人肉目录 |
| **妆面样片 / 作品集**（用户上传图片给顾客看） | 上传本身零技术障碍，卡住的是「给谁看」：**给顾客看就是 UGC 公开内容，不给看又对她本人零价值** |
| **支付 / 收费** | 一有交易就落进「电商平台」类目，个人主体**根本没有这一项** |

留下来的东西反而更锋利了。比如顾客端那个「我约过的妆娘」列表：

> **它的长度 = 你自己约过几个人，不是平台上注册了几个人。**
> 一次都没约过的人永远不出现；反过来说，你约过谁，这一页就只有谁。

这不是一个功能取舍，是**在个人主体下唯一合规的形态**。类似地，微信号被隔离在单独一个数据集合里，全项目只有**一个函数**能把它读出来 —— 因为「顾客能看到谁的微信」这件事，一旦有第二条路，就等于没做隔离。

## 怎么跑

1. 微信开发者工具 → 导入项目 → 选 `妆历小程序/` 目录
2. AppID 选「测试号」即可，**不需要**配置任何后端或云环境
3. 想跑自测：仓库根目录 `node "妆历 自测.js"`

⚠️ 开发者工具的热重载偶尔会让页面看起来「点不动」—— 关掉重开就好，**不是代码问题**（这个坑我查了三轮）。
