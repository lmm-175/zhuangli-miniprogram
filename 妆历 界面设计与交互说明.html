化妆师的排班本 + 接单本。本文件逐个界面给出屏幕布局与每一个交互控件的名称、位置、点击后的行为。 所有界面按「个人主体 + 工具类目」口径设计，红底行 = 类目红线，不可实现。

v1.0 · 2026-09-29 14 个页面 ⛔ 类目红线：金额不得出现在顾客端 工具-预约/报名 + 工具-日历
设计规范 类目红线 顾客端（5） 化妆师端（10） 按钮总表 状态与流程 交互规则

2类目红线速查【先看这一节】

依据 微信开放文档___开放的服务类目.md 个人主体部分（1141–1215 行）。 本文件后面每个界面的规格表里，红底行 = 违反红线，开发时不可实现。

⚠️ 最要命的一条：非个人主体有平台类目可申请，个人主体的 8 个大类里没有任何一个是平台性质。 所以被判「多商户平台」不是补资质能解决的，是无解。
下面 4 条红线不是「尽量避免」，是「唯一活路」。
红线 1 · 作品集不能「公开可访问」

个人主体没有「社交」大类；「工具-图片处理」明写"如提供传播和公开访问服务，属于社交范畴"。

⛔ 点赞 / 评论 / 收藏 / 浏览数 / 转发数
⛔ 作品列表页、「更多作品」入口
⛔ web / H5 版本、二维码广场
✅ 落地页 = 这个妆娘的个人页
✅ 用词「妆面样片」不用「用户原创内容」
红线 2 · 金额不得出现在顾客端

个人主体可以有金额（「记账」就是消费记录）。违规的是"这个数字构成一次服务要约"+"分享给顾客"。

⛔ 顾客端出现任何货币符号 / 金额
⛔ 妆位带价格字段
⛔ 另需服务在顾客端显示加价
✅ 妆娘自己的设置页可以有金额
✅ 定金只标「已收 / 未收」不带金额
红线 3 · 漫展名必须自由文本
⛔ 平台维护的漫展枚举字典
⛔ 「展会页」（按漫展聚合多个妆娘）
⛔ 「该漫展下的其他妆娘」
✅ 妆娘自由文本输入漫展名
红线 4 · 措辞禁令
禁用入驻 · 平台 · 商家 · 店铺 · 下单 · 订单 · 购买 · 支付 · 价格 · 报价 · 费用 · 套餐 · 优惠 · 社区 · 广场 · 关注 · 粉丝 · 收藏 · 点赞 · 评论
改用化妆师登记 · 预约单 · 另需服务 · 妆面样片 · 作品集 · 我的预约
「我的预约」（交易记录 ✅）≠「我的化妆师」（收藏关系 ⛔）。
个人版「信息查询」比非个人版少了「订单」二字 —— 个人主体没有"订单功能"这个口径。

6状态机与关键流程

6.1 预约单状态机

pending
提交即占位 → confirmed → done
pending → rejected ⚠️ 释放妆位 ／ cancelled ⚠️ 释放妆位
⚠️ rejected / cancelled 必须真的释放妆位。 改状态但忘了放锁，妆位就永久废了——这是本模块最容易漏的一行代码。

妆位是否可约 = 该妆位不存在 status ∈ {pending, confirmed} 的单。 这个判断同时服务三处：落地页可约标记 · 提交时并发校验 · 妆娘端列表。只能有一处实现。

6.2 妆娘的三个高频动作路径

路径 1 · 排档期 → 分享（每场漫展一次）
A1 工作台→A4 新建档期→ A5 快捷生成→A5 存为模板→ A5 分享
路径 2 · 处理预约单（每天）
A1 待处理计数→A7 列表→ A8 详情→复制微信号→ 标记定金→确认这单
路径 3 · 代填（冷启动唯一抓手）
A1 新建预约单→A9 选妆位→ （若冲突）强制占位→填信息→ 提交
📌 不需要顾客存在、不需要顾客用小程序、不需要顾客同意。 妆娘今天接了个客，晚上顺手录进去——她得到的是「记住了」。
路径 4 · 顾客（只发生一次）
点开卡片→C1 选妆位→ C2 填表→提交→ C5 成功
⚠️ 妆娘在 A8 点「拒绝」时，顾客没有任何通道能收到通知。所以 C1 的预期说明条是必需的，不是装饰。

6.3 通知能力边界（决定了整个交互设计）

方向能不能发所以交互怎么设计
妆娘 → 顾客发不出顾客不是订阅者。→ 妆娘只能靠微信原生好友申请联系他
顾客 → 妆娘发不出→ 妆娘靠 A1 的待处理计数 代替推送。通知失效的后果 = 无后果，单子在那儿等着
系统 → 妆娘可以订阅消息（一次性）。⚠️ 但 v1 不做推送——A1 的计数已足够
📌 整个流程是异步的，这是本产品的结构性优势。
对比被砍掉的「戳戳」：用户戳 → 妆娘必须被实时通知才能确认 → 通知做不到 → 链路死锁。
妆位单把「谁暴露联系方式」反过来（用户留自己的微信，妆娘来加），通知就不再是必需环节了。

7通用交互规则

7.1 加载与反馈
提交类按钮点击后立即置 loading 态 + 禁用，防重复提交（预约单会重复占位）
网络失败Toast「网络不好，请重试」+ 按钮恢复可点，已填内容不丢
复制类按钮Toast「已复制」+ 引导文案（如「去微信添加好友」）
危险操作拒绝 / 删除 / 强制占位 → 一律二次确认，文案要说清后果
7.2 空态
A7 预约单为空「还没有预约单」+ 引导去分享妆位
A6 模板为空「还没有模板。在档期编辑页排好妆位后，点【存为模板】」不放跳转按钮
A5 妆位为空「还没有排妆位」+ 三个按钮（快捷生成 / 套用模板 / 手动加）
C4 我的预约为空纯文案。⛔ 绝不能放「浏览化妆师」按钮
7.3 二次确认清单【必须弹】
拒绝预约单「拒绝后妆位将释放给其他人」
作废冲突单并强制占位「将作废阿澈的预约单」
删除妆位（已被约）「该妆位有预约单，请先处理」← 其实是阻断不是确认
删除档期 / 模板「删除后不可恢复」
放弃填了一半的表单「放弃填写？已填内容将不保留」
7.4 🔴 三处最容易写错的接口约束
booking_form.contact_*绝不进列表接口。只由 getBookingDetail 校验「请求者是否为该单妆娘」后单独返回
artists.wechat_id绝不进主页 / 分享页通用接口返回值。只由 showContact 校验后单独返回
user_profiles.*（整表）妆娘端任何接口都不得返回。只能以 booking_form 快照形式、且只对该单妆娘可见
📌 这三个是本项目最容易写错、也最致命的三处。图省事直接查档案表返回给妆娘端就完了。

7.5 为什么顾客端「没有」某些东西【写给审核，也写给未来的自己】

顾客端没有不是遗漏，是决定
首页 / 搜索 / 浏览「发现」这件事交回给小红书和微信。本产品只负责接住已经发生的预约
注册 / 授权 / 绑手机身份靠 wx.login 静默取得。「顾客有身份」和「零门槛」不冲突
评价 / 收藏 / 关注评价 = 评论 = 社交，个人主体没有「社交」类目
点赞 / 评论 / 浏览数作品集被展示，不被互动（红线 1）
金额 / 价格 / 定金 ¥X金额只存在于「只有妆娘自己看」的界面（红线 2）
「浏览化妆师」入口包括「我的预约」的空态。这条防线不能有任何一个后门
⚠️ 最后再说一次：非个人主体有平台类目可申请，个人主体的 8 个大类里没有任何一个是平台性质的。 被判「多商户平台」不是补资质能解决的，是无解。

所以上面这些「没有」，不是「尽量避免」，是「唯一活路」。
